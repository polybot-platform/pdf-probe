# Test corpus

Synthetic PDFs, generated by script. There are no real documents here, and the generated files are not committed (`corpus/out/` is ignored).

```
bun install
bun run corpus      # writes corpus/out/*.pdf (needs Ghostscript `gs` on the PATH for the gs-* cases)
bun run reference   # runs pdf.js over them -> corpus/reference-results.json
bun run diff corpus/reference-results.json   # compares a results file with corpus/expected-pdfjs.json
bun run poppler     # runs poppler's pdfinfo over them -> corpus/poppler-results.json (needs poppler-utils)
bun run tools/diff-results.ts corpus/expected-pdfjs.json corpus/poppler-results.json
bun run samples && bun run samples:reference && bun run samples:poppler && bun run samples:diff   # pdf.js's own test PDFs, see below
```

`bun run diff` exits non-zero on any unexpected difference. Run on pdf.js's own results it reports one `STALE intended difference` (`empty-page-tree.pdf`), because pdf.js by definition does not make the intended change. That is the expected self-check output.

`expected-pdfjs.json` is what pdf.js 6.4.299 (through unpdf 2.1.0) returns for each file: the page count, every page's size in points, and a verdict (`null` readable, `pageSize` for a page over 17.5 x 12 inches, `unparseable`; a candidate may also return `empty`, see Intended differences). The size limit is an example policy for the test, not part of the library. A candidate's results file has the same shape.

## What is covered

| Generator | Cases |
|---|---|
| `generate-classic.ts` | Classic xref; inherited and indirect MediaBox; CropBox smaller and larger; `/Rotate` (90, 270, negative, 45, inherited); `/UserUnit`; reversed and zero-area boxes; nested trees; `/Count` over and under; page-tree cycle; kid without `/Type`; empty tree; broken offsets, `startxref` and missing xref; truncation; trailing junk; garbage header; incremental update that removes a page and one that adds an oversize page; non-PDFs; Ghostscript output (classic, linearized, RC4) |
| `generate-modern.ts` | Xref streams and object streams (the page tree exists only inside compressed data); Flate with PNG predictors; incremental updates over xref streams; a hybrid-reference file; RC4-128, RC4 under V4 with a 40 or 48-bit key, AES-128 and AES-256 (R6) encryption with an empty user password, with the page tree inside an encrypted object stream; the same with a user password set (must fail) |

## Intended differences

The gate is "identical to pdf.js" except for the fixtures listed, with reasons, in [`intended-differences.json`](intended-differences.json). A listed fixture must match its listed expectation and must differ from pdf.js; if a candidate starts matching pdf.js again, the entry is reported as stale. Every other difference fails.

| Fixture | pdf.js | pdf-probe | Why |
|---|---|---|---|
| `empty-page-tree.pdf` | readable, 0 pages | failure, kind `empty` | A document with no pages has nothing to count; a caller checking `pages <= cap` would let it through. Its own kind, not `unparseable`: the file is well-formed, just empty |

Deliberately **not** differences, because the library matches pdf.js: trusting `/Count` (`count-undercounts.pdf`, `count-overcounts.pdf`), failing on a page-tree cycle, failing on a user password, and failing on a missing or truncated cross-reference table. Gemini follows `/Count` too, so a stricter count would reject files the model accepts.

## poppler as a third opinion

`bun run poppler` runs `pdfinfo` (poppler 24.02.0) over the corpus in the same results shape. It reports what poppler says and does not try to agree with pdf.js. Against `expected-pdfjs.json`, 55 of 65 fixtures are identical. The ten that differ are the six below plus the four short-key RC4 files:

| Fixture | pdf.js | poppler `pdfinfo` | What it tells us |
|---|---|---|---|
| `userunit-0.5.pdf`, `userunit-2-oversize.pdf`, `xrefstm-objstm-rotate-userunit.pdf` | `/UserUnit` applied | `/UserUnit` ignored | A limit of `pdfinfo`, which prints the box size only. Poppler gives no opinion on `/UserUnit` |
| `page-tree-cycle.pdf` | fails (`unparseable`) | logs `Loop in Pages tree`, exits 0, reports 2 pages with the second `0 x 0` | `pdfinfo` does not fail closed on a cycle. The runner keeps the log line in a `note` field. Earlier notes saying poppler "detects the loop" meant this log line only |
| `count-overcounts.pdf` (`/Count 500`, one page) | 1 page | fails: `Page count (500) larger than number of objects (4)` | A real disagreement. Poppler is stricter than pdf.js on an over-count. What Gemini does with an over-count was not tested, so the library follows pdf.js until it is |
| `enc-rc4-v4-40-*` and `enc-rc4-v4-48-*` with an empty password (4 files) | readable | fails: `Unknown compression method in flate stream` | `pdfinfo` derives the per-object keys without zero-extending a short V4 key to 16 bytes, as pdf.js and the real-world files do. Same failure as pdf.js's `issue19484_1` and `_2` |
| `empty-page-tree.pdf` | readable, 0 pages | fails: `Invalid page count 0` | Agrees with the intended difference. Poppler cannot say `empty`, so the runner reports `unparseable` |

Use poppler to break a tie between the library and pdf.js on fixtures other than `/UserUnit`. On `/UserUnit` it is silent, and on a cycle read its `note` rather than the verdict.

## pdf.js's own test PDFs

`bun run samples` fetches the 987 PDFs committed under `test/pdfs` in pdf.js v6.4.299 (commit `d0991a0`, 121 MB) into `corpus/pdfjs-samples/`, which is git-ignored. They are **not** copied into this repository: the files carry no per-file licence or provenance, and some came from third-party bug reports, so we cannot say they are free of personal data or that we may redistribute them. The fetch is pinned and checked against the commit hash. Run the tools over them; do not commit or republish them.

`bun run samples:reference` and `bun run samples:poppler` write results in the usual shape, and `bun run samples:diff` compares them. The expected values are whatever pdf.js returns on that checkout, so nothing about these files is stored here.

pdf.js and poppler agree on 962 of the 987. The 25 that differ are triaged in [`triage-pdfjs-samples.md`](triage-pdfjs-samples.md): 23 stay "match pdf.js" and 2 are intended differences (`Brotli-Prototype-FileA.pdf` and `poppler-85140-0.pdf`, in `intended-differences.json`). The seven files that pdf.js rejects and poppler reads all stay failures. One fixture is still to write: a hybrid file shaped like `issue9418`. The RC4 short-key fixtures (`enc-rc4-v4-40-*`, `enc-rc4-v4-48-*`) are written.

## Known caveats

- `hybrid-reference-oversize.pdf` was malformed in the first version (the classic table marked the compressed objects free, so pdf.js and poppler never reached the `/XRefStm`). It now omits them from the table's subsections, and pdf.js and poppler agree: 1 page, 1700 x 2400 pt.
- The encrypted fixtures use random keys and IDs, so their bytes differ on every run. The results do not.
- `expected-pdfjs.json` records pdf.js's behaviour, not the truth. Where pdf.js and poppler disagree with what a reader should do, say so in the differential test as an intended difference.
- `count-undercounts.pdf` (a tree of 5 pages with `/Count 2`) reads as 2 pages in pdf.js and poppler. That is the behaviour to match.
